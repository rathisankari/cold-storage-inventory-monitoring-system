# Problem Statement

## 1. Title
ColdGuard – Real-Time Cold Storage Inventory Monitoring System

## 2. Domain
HealthTech / Supply Chain & Logistics — Pharmaceutical Cold Chain Monitoring

## 3. Who is the user?
- **Storage Operator** — logs and monitors temperature readings for storage units under their charge, responds to alerts
- **Compliance / Logistics Admin** — configures temperature thresholds per vaccine/medicine category, views system-wide dashboards, pulls compliance reports, manages storage units and staff access
- **(Optional, Phase 3) Delivery/Transport Handler** — logs handoff temperature checks during transport legs

## 4. What problem are we solving?
Vaccines and temperature-sensitive medicines must be kept within a strict range (commonly 2°C to 8°C, with some vaccines requiring -50°C to -90°C) from manufacture until administration. According to WHO/UNICEF and industry cold-chain reports, published cold-chain literature places annual vaccine spoilage due to temperature excursions in a wide range, roughly 25-50% depending on region and source (see docs/Literature_Review.md) — and because a spoiled vaccine is visually indistinguishable from a good one, this often goes undetected until lab testing or, worse, after the dose has already been administered to a patient who is then wrongly assumed to be protected. Today, temperature checks in many storage facilities are manual and periodic (a worker checking a thermometer every few hours) rather than continuous, meaning a dangerous drift can go unnoticed for hours. A system that continuously monitors storage temperature, detects abnormal trends before they become critical, and maintains a tamper-proof record of every reading would directly reduce this silent spoilage.

## 5. Proposed Solution
- Temperature data is received through a simulated IoT sensor API during development, allowing future integration with physical IoT devices without architectural changes
- Configurable safe-temperature thresholds per storage category (Normal 2-8°C, Deep-Frozen, Ultra-Cold -50 to -90°C — matching real WHO vaccine categories)
- Real-time dashboard showing live status of every monitored storage unit
- Automatic alerting (email/SMS) to the responsible operator/admin the moment a threshold is breached
- Anomaly/trend detection (Day 41-60 AI enhancement) — flags a unit trending toward a breach before it actually happens, using rate-of-change analysis on recent readings
- Tamper-proof, append-only logging of every reading and every alert (audit trail) — logs cannot be edited or deleted, only appended
- Compliance reporting: exportable history proving a given batch/unit stayed within safe range for its full storage duration

## 6. Core Entities / Database Tables
1. **User** (login, role: operator/admin, contact info)
2. **StorageUnit** (physical fridge/freezer, with temperature category and safe-range built in)
3. **Inventory** (medicine/vaccine batches stored in a unit — name, batch number, quantity, expiry)
4. **TemperatureLog** (timestamped reading, linked to StorageUnit — insert-only, no edit/delete API)
5. **Alert** (triggered event: which unit, breach type, timestamp, resolved status — insert-only)
6. **ComplianceReport** (stored record of a generated report — type, generated by, file location)
7. **AuditLog** (append-only record of admin actions on users/storage units/inventory)

## 7. User Roles & Permissions
| Role | Permissions |
|---|---|
| Storage Operator | View assigned storage units, view/acknowledge alerts, cannot edit thresholds or delete logs |
| Compliance/Logistics Admin | Full access — manage storage units, configure thresholds per category, view all dashboards, export compliance reports, view full audit log |

## 8. Success Criteria
- Dashboard updates within 5 seconds of a new temperature reading being ingested
- A threshold breach triggers a visible alert and a notification (email/SMS) within 1 minute
- Report generation completes within 5 seconds for any storage unit's full history
- No reading or alert record can be edited or deleted through any interface (verified via audit log integrity check)

## 9. Out of Scope
- Integration with actual physical IoT temperature sensor hardware — data is ingested via a simulator built to mimic realistic sensor behavior
- Full multi-leg transport/route tracking (air/sea/road logistics) — this project focuses on storage-unit monitoring, not the full transport journey
- Payment or procurement features
- Mobile native app (web-responsive only)

## 10. Chosen Track: Python (FastAPI) — React frontend
